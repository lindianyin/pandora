## 1. 文档说明

### 1.1 目的

定义 **比鸡玩法** 的功能需求、非功能需求与验收标准，作为后续 SPEC、协议、服务端与网页客户端实现的依据。平台级能力（登录、钱包、背包、活动、运营后台）以 `docs/棋牌游戏服务端-需求文档.md` 为准，本文只描述比鸡差异与增量。

### 1.2 范围

**包含**

- 场次选择、匹配入座、准备开局
- 发牌、摆牌（头墩/中墩/尾墩）、确认提交
- 三墩比牌、名次结算、金币账变
- 特殊牌型「吃喜」简化表（首发启用，见 §3.5）
- 断线托管与重连
- 简易 Web 对局页 + 多端 lab（如 `/biji-lab`）
- 运营可配：底分、人数、准入、超时、开关

**不包含（本期）**

- 带大小王的六人变体（预留扩展）
- 5 人无王 / 旁观
- 朋友场房卡、冲榜
- 录像回放完整产品化（可先有对局日志）
- 复杂 AI 陪玩（超时用固定启发式代摆即可）

### 1.3 术语

| 术语 | 说明 |
|------|------|
| 墩 | 三张牌组成的一组；一局每人三墩：头墩、中墩、尾墩 |
| 头/中/尾 | 必须满足 **头墩 ≤ 中墩 ≤ 尾墩**（牌型与比牌规则下的大小），否则为「倒水」非法摆牌 |
| 摆牌 | 玩家将 9 张手牌分配到三个墩并确认 |
| 比牌 | 所有人确认（或超时）后，按墩依次比较并结算 |
| 牌型 | 单墩的类型：三条、同花顺、同花、顺子、对子、单张（散牌） |
| 底分 | 场次 `base_score`；结算倍数乘底分得金币 |
| 倒水 | 摆牌违反头≤中≤尾；须拒绝确认或超时由系统代摆合法牌 |
| 吃喜 | 特殊全盘牌型触发的额外奖励；首发用 §3.5 简化表 |
| 服务端权威 | 发牌、牌型判定、比牌输赢、金币账变均以服务端为准 |

### 1.4 假设与约束

- 复用 Pandora：**游客登录、金币钱包、大厅模板、`IRoomGame`/`GameRegistry`、Admin 场次、活动钩子、对局日志 `LogRound`**。
- `game_id` 四位号段，建议首发 **`6000`**（经典比鸡）；变体预留 `6001–6099`。玩法消息：`msg_id = game_id * 100 + slot`（`600000–600099`）；玩法错误码：`err = game_id * 1000 + slot`（`6000000+`）。
- 短名建议：`biji`（日志 / ClientTrace）。
- 比鸡为 **回合/阶段制**（发牌→摆牌→比牌结算），非捕鱼类实时 tick 玩法；倒计时与托管对齐杭麻/跑胡子模式。
- 不做微服务拆分；牌桌状态在房间内存，结算走 `WalletService` + `ledger` 幂等。
- 首发人数：**2–4 人**（最大 4，不做 5 人无王）；匹配凑满模板 `players` 后建房；**不允许旁观**。
- **禁止**客户端自报牌型或输赢；客户端只上报墩内牌序/确认，服务端校验合法性并结算。

## 2. 系统概述

### 2.1 产品目标

在现有棋牌大厅增加 **比鸡金币场**：选场 → 入座准备 → 发 9 张 → 摆三墩 → 比牌结算。体验强调「摆牌策略感、三墩依次亮牌的戏剧性、结算清晰」；数值上底分 × 名次倍数可控，便于运营调场。

### 2.2 与平台关系

```
[网页客户端] --WSS--> Pandora 单体
                         │
              ┌──────────┼──────────┐
              ▼          ▼          ▼
           大厅/匹配   比鸡 RoomGame   钱包/活动/后台
              │          │
              │     game_id=6000
              │     BijiTable 状态机
              └──────────┘
```

- 匹配：复用 `room_template`（`game_id=6000`）。
- 对局：实现 `IRoomGame`（如 `BijiRoomGame`），`GameRegistry` 注册；规则在 `BijiTable`。
- **禁止**再往 `Room` 增加比鸡平行字段。

### 2.3 核心用户路径

1. 登录 → 大厅「比鸡·初级场」  
2. 快速匹配凑齐 2–4 人 → 入座  
3. 全体准备 → 发牌（每人 9 张）  
4. 摆牌阶段：分配头/中/尾并确认  
5. 全员确认或超时 → 三墩依次比牌动画/广播  
6. 结算金币 → 可再准备下一局或离开

## 3. 规则需求（权威摘要）

细则落地后同步 `docs/比鸡游戏规则.md`；与本文冲突时以 **已确认的 SPEC + 规则文档** 为准。以下为需求级默认（安徽/溧阳常见无王玩法）。

### 3.1 牌具与人数

| 项 | 首发默认 |
|----|----------|
| 牌副 | 一副扑克去掉大小王，**52 张** |
| 人数 | **2–4 人**（最大 4；每人 9 张；4 人用满 36 张，余牌不发） |
| 发牌 | 逆时针一张张发，每人 9 张；**首局随机起始座位，之后由上局尾墩第一名的下家起发** |

### 3.2 单墩牌型（大 → 小）

```
三条 > 同花顺 > 同花 > 顺子 > 对子 > 单张（散牌）
```

| 牌型 | 定义 | 同型比较（摘要） |
|------|------|------------------|
| 三条 | 三张同点 | 比点数 |
| 同花顺 | 同花色且连续 | 比顺子大小；再比花色 |
| 同花 | 同花色非顺 | 从大到小比点；再比花色 |
| 顺子 | 连续非同花；**A23 最小，QKA 最大** | 比最大张；再比花色 |
| 对子 | 一对 + 单张 | 比对子点，再比单张；再比花色 |
| 单张 | 其余 | 从大到小比点；再比花色 |

**点数**：A 最大（仅在顺子中 A23 作最小），以下 K…2。  
**花色**：黑桃 > 红桃 > 梅花 > 方块；**同型同点须比花色**，打破平局，无并列。

### 3.3 摆牌约束

- 每墩恰好 3 张；三墩合起来必须是发到的 9 张（无换牌）。  
- 必须 **头墩 ≤ 中墩 ≤ 尾墩**（按 §3.2 完整比较序）。  
- 非法提交：返回错误，不进入比牌；超时未确认：服务端按策略代摆（见 FR-BIJI-33）。

### 3.4 比牌与名次结算

1. 三墩分别比较：所有玩家的头墩比一次，中墩一次，尾墩一次。  
2. 每一墩严格用花色打破平局，**无并列**。  
3. **按墩结算**：以该墩第一名为收款方，其余名次按档位赔付。**4 人局基准表**；2/3 人局对「相对第一名的名次」**同比缩放**（只保留存在的名次档）：

| 相对第一名的名次 | 赔付倍数（× 底分） | 2 人局 | 3 人局 | 4 人局 |
|------------------|-------------------|--------|--------|--------|
| 第 2 名 | 2 | ✓ | ✓ | ✓ |
| 第 3 名 | 4 | — | ✓ | ✓ |
| 第 4 名 | 6 | — | — | ✓ |

例：2 人局仅第 2 名赔 2×底分；3 人局第 2/3 名分别赔 2×、4×底分。

4. 一局总输赢 = 三墩结算之和 + 吃喜（§3.5）。  
5. **抽水**：按场次 `rake_bp` 从**本局净盈利的赢家**盈利中抽取（与平台斗地主等赢家抽水对齐）。

### 3.5 吃喜（首发启用 · 简化表）

满足下列**全盘**条件时，在三墩结算之外额外结算「吃喜」。倍数相对 **底分**；由桌上其他每人付给吃喜者（多人同时吃喜则各自独立结算）。同类只取最高一档，不叠加。

| 吃喜类型 | 条件（摘要） | 倍数（× 底分，每人付给） |
|----------|--------------|--------------------------|
| 三墩三条 | 头/中/尾均为三条 | 12 |
| 三墩同花顺 | 头/中/尾均为同花顺 | 10 |
| 三墩同花 | 头/中/尾均为同花（含同花顺按更高档） | 6 |
| 三墩顺子 | 头/中/尾均为顺子（含同花顺按更高档） | 6 |
| 全黑 / 全红 | 9 张均为黑色花色（♠♣）或均为红色（♥♦） | 4 |

说明：同花顺同时满足「三墩同花」「三墩顺子」时只按「三墩同花顺」计；全色可与三墩类**叠加**（简化表允许：先三墩档再全色档）。细则在规则文档与 SPEC 用牌例锁死。

## 7. 状态机（牌桌）

```
WaitReady → Deal → Arrange → Compare → Settle → WaitReady
                ↘（解散/全离）→ Closed
```

| 状态 | 行为 |
|------|------|
| WaitReady | 入座、准备；全员准备 → Deal |
| Deal | 洗牌发牌 → Arrange |
| Arrange | 接受摆牌/确认；全锁或超时 → Compare |
| Compare | 服务端算分并广播逐墩结果 → Settle |
| Settle | 账变、结算面板 → WaitReady（或结束房间） |

## 8. 验收标准（首发 P0）

1. 大厅可匹配 `game_id=6000`，2–4 人开局并发 9 张。  
2. 合法摆牌可确认；倒水拒绝；超时有合法代摆。  
3. 三墩比牌结果与 §3 规则一致（单测覆盖牌型序与花色打破平局）。  
4. 结算金币与底分、名次倍数（含 2/3 人同比缩放）一致；吃喜按 §3.5；赢家 `rake_bp` 抽水；ledger 可查且幂等。  
5. 断线重连可继续摆牌或看到比牌/结算；超时固定启发式代摆合法。  
6. 顶号旧端失去操作权；无旁观。  
7. Web 正式桌 + `/biji-lab` 可完成「摆牌→比牌→金币变化」闭环。  
8. 模板关闭后不可再匹配；起发座位按「上局尾墩第一名下家」。
