## 1. 文档说明

### 1.1 目的

定义 **捕鱼玩法** 的功能需求、非功能需求与验收标准，作为后续 SPEC、协议、服务端与网页客户端实现的依据。平台级能力（登录、钱包、背包、活动、运营后台）以 `docs/棋牌游戏服务端-需求文档.md` 为准，本文只描述捕鱼差异与增量。

### 1.2 范围

**包含**

- 捕鱼场次选择、进入/离开渔场（房间）
- 鱼群刷出、游动、离场；玩家开炮、子弹飞行、命中与结算
- 炮台倍率、锁定/狂暴等基础技能（首发可裁剪）
- 金币消耗与捕获奖励；断线重连与托管（离场代打策略）
- 简易 Web 联调页（`/fish-lab` 或大厅入口）
- 运营可配：场次底分/炮倍区间、鱼种表、掉落期望、开关

**不包含（本期）**

- 3D/精美特效与完整美术管线
- 真人对战竞技榜、跨服大奖赛
- 实物兑换、直播带货类玩法
- 客户端物理引擎级精确碰撞（服务端权威简化判定即可）

### 1.3 术语

| 术语 | 说明 |
|------|------|
| 渔场 / 房间 | 多名玩家同屏的捕鱼逻辑房间（共享鱼群场景） |
| 座位 | 渔场内固定炮位（建议 4 坐：下/左/上/右） |
| 炮台 | 玩家武器；有炮倍（火力），开火消耗金币 |
| 炮倍 | 单发消耗 = 炮倍 × 场次底分系数（见配置） |
| 子弹 | 开火生成的飞行体；命中后结算或穿透（按鱼种） |
| 鱼种 | 配置表中的鱼类型：血量/分值/出现权重/特殊效果 |
| 捕获 | 命中结算成功，鱼离场并发奖 |
| 击破 | 对「血量鱼」扣血至 0 后捕获；「概率鱼」按期望概率判定 |
| 场景波次 | 刷鱼节奏：普通潮 → 高潮 → BOSS 潮（可配） |
| 锁定 | 子弹自动追踪目标鱼（消耗或限时技能） |
| 服务端权威 | 开火扣费、命中、发奖以服务端为准；客户端表现跟随 |

### 1.4 假设与约束

- 复用 Pandora：**游客登录、金币钱包、大厅模板、`IRoomGame`/`GameRegistry`、Admin 场次热更、活动发奖钩子**。
- `game_id` 使用四位号段，建议首发 **`5000`**（经典捕鱼）；变体预留 `5001–5099`。玩法消息：`msg_id = game_id * 100 + slot`（`500000–500099`）。
- 捕鱼为 **实时帧同步倾向** 玩法：服务端按固定 tick 推进鱼群与子弹，而非回合制。
- 不做微服务拆分；渔场状态在房间进程内内存，结算走既有 `WalletService` + `ledger` 幂等。
- 首发人数：**每桌 1–4 人**（可少人开局，允许单人练习场）。
- 公平性：禁止客户端自报「打中了就给钱」；客户端只上报开火意图与瞄准参数，命中由服务端算。

## 2. 系统概述

### 2.1 产品目标

在现有棋牌大厅中增加 **捕鱼金币场**：玩家选场 → 入座 → 开炮捕鱼赚金币 → 结算离场。体验上强调「同屏热闹、开炮即时反馈、大奖鱼偶发」，数值上可控 RTP（长期返还率），便于运营调参。

### 2.2 与平台关系

```
[网页客户端] --WSS--> Pandora 单体
                         │
              ┌──────────┼──────────┐
              ▼          ▼          ▼
           大厅/匹配   捕鱼 RoomGame   钱包/活动/后台
              │          │
              │     game_id=5000
              │     渔场状态机 + tick
              └──────────┘
```

- 匹配：复用 `room_template`（`game_id=5000`，`players=1~4`）。
- 对局：实现 `IRoomGame`（如 `FishRoomGame`），由 `GameRegistry` 注册。
- 不再往 `Room` 增加平行字段。

### 2.3 核心用户路径

1. 登录 → 大厅看到「捕鱼·初级场」等模板  
2. 快速匹配 / 选场进入渔场  
3. 分配座位与初始炮倍；场景开始刷鱼  
4. 瞄准开炮 → 扣金币 → 命中反馈 → 捕获加币  
5. 可换炮倍、使用锁定（若开启）  
6. 主动离开或断线；余额以钱包为准

### 5.1 场次模板（复用 `room_template`）

| 字段 | 说明 |

### 5.2 鱼种 / 波次配置（MySQL，示意）

| 字段 | 说明 |
|------|------|
| fish_type | 稳定 ID |
| name | 显示名 |
| score | 分值（奖励倍率基础） |
| kind | `odds` 概率鱼 / `hp` 血量鱼（**两者均首发**） |
| hp | 血量鱼最大生命 |
| weight | 刷出权重 |
| radius | 碰撞半径 |
| special | 无 / 炸弹 / BOSS 等 |

### 5.3 账变类型（示意）

| 场景 | 币种 | 方向 | 幂等键示例 |
|------|------|------|------------|
| 开火消耗 | 金币 | 扣 | `fish:fire:{round}:{uid}:{seq}` |
| 开火抽水 | 金币 | 扣（或账变备注/子类型标记抽水份额） | 与开火同一业务序号关联 |
| 捕获 | 金币 | 加 | `fish:catch:{round}:{fish_inst}:{uid}` |

详细字段在后续 `docs/捕鱼游戏-SPEC.md` 与 `proto/game_fish.proto` 锁定。需求级消息包括：

| 方向 | 用途 |

## 7. 状态机（渔场）

```
WaitReady → Playing → (可选) SettlingLeave → Closed
```

- **WaitReady**：等人入座；`min_players` 满足且（可选）倒计时结束 → Playing  
- **Playing**：刷鱼 + 接受开火；全员离开或房间到期 → Closed  
- 首发可不做「整局结算面板」，以实时金币为准；离开即清座位  

---

## 8. 验收标准（首发 P0）

1. 大厅可匹配进入 `game_id=5000` 渔场，1–4 人同屏可见彼此开火。  
2. 开火必扣金币；余额不足无法开火；账变可查且幂等。  
3. 捕获加币与鱼种分值、底分一致；刷新页面/重连后余额正确。  
4. 断线不开炮、不误扣；重连恢复场景与座位。  
5. 同账号第二端登录，旧端收到踢人并退出渔场操作权。  
6. 非法炮倍、超频开火被拒绝并返回统一错误码。  
7. 提供 Web 渔场页 + **多端 lab**，可完成「开炮→打到鱼→金币变化」闭环。  
8. 鱼种/波次在 DB 可配可热更；关闭模板即不可再匹配。  
9. 开火按 `rake_bp` 抽水；概率鱼与血量鱼均可捕获结算。
