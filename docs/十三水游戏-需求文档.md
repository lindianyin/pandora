> **玩法界定**：本文「十三水」指华东/华南常见的 **每人 13 张扑克、分头墩 3 / 中墩 5 / 尾墩 5 比牌计「水」**（亦称十三张、罗宋），**不是**比鸡（每人 9 张三墩）也不是德州扑克。若产品要做庄闲下注版或带鬼牌变体，须在本文 §10 明确或另开需求。

> **与比鸡关系**：流程同为「发牌 → 摆牌 → 比牌结算」，但牌数、墩结构、牌型序、水数结算、打枪与特殊牌型均不同；**禁止**复用 `BijiTable` 硬编码规则，应独立 `SssTable`（或等价命名）+ 独立协议。

## 1. 文档说明

### 1.1 目的

定义 **十三水玩法** 的功能需求、非功能需求与验收标准，作为后续规则文档、SPEC、协议、服务端与网页客户端实现的依据。平台级能力（登录、钱包、背包、活动、运营后台）以 `docs/棋牌游戏服务端-需求文档.md` 为准，本文只描述十三水差异与增量。

### 1.2 范围

**包含**

- 场次选择、匹配入座、准备开局
- 发牌、摆牌（头/中/尾）、确认提交；可选「特殊牌型报到」
- 普通三墩比牌、打枪、全垒打、特殊牌型结算、金币账变
- 倒水（非法摆牌）处理
- 断线托管与重连
- 简易 Web 对局页 + 多端 lab（如 `/sss-lab`）
- 运营可配：底分、人数、准入、超时、开关、是否启用特殊牌型/打枪

**不包含（本期）**

- 大小王 / 鬼牌变体、五同（五张同点）扩展
- 马牌（额外加分牌）、旁观、朋友场房卡、冲榜
- 真人庄闲下注桌（赌场式）
- 录像回放完整产品化（可先有对局日志）
- 复杂 AI 陪玩（超时用固定启发式代摆即可）

### 1.3 术语

| 术语 | 说明 |
|------|------|
| 墩 | 一组牌；一局每人三墩：头墩 3 张、中墩 5 张、尾墩 5 张 |
| 头/中/尾 | 必须满足 **头墩 ≤ 中墩 ≤ 尾墩**（按 §3 完整比较序），否则为「倒水」 |
| 摆牌 / 组牌 | 玩家将 13 张手牌分配到三个墩并确认 |
| 比牌 | 全员确认（或超时）后，按墩两两比较并累计水数 |
| 水（水数） | 结算单位；金币 = 水数 × 场次底分（`base_score`） |
| 乌龙 | 五张不成对、不成三条、非顺非同花的散牌（最低牌型） |
| 铁支 | 四条（四张同点 + 一张散牌） |
| 葫芦 | 三条 + 一对 |
| 倒水 | 摆牌违反头≤中≤尾；确认拒绝，或超时由系统代摆；若已进入比牌仍非法则通赔（见 §3.6） |
| 打枪 | 一家对另一家 **三墩全胜**；该对局二人之间水数按倍数结算 |
| 全垒打 | 一人对桌上其余每人皆打枪；再按规则加倍 |
| 特殊牌型 / 报到 | 全盘 13 张满足特定组合时，不走普通三墩逐墩比，按特殊水数直接结算 |
| 服务端权威 | 发牌、牌型判定、水数、金币账变均以服务端为准 |

### 1.4 假设与约束

- 复用 Pandora：**游客登录、金币钱包、大厅模板、`IRoomGame`/`GameRegistry`、Admin 场次、活动钩子、对局日志 `LogRound`**。
- `game_id` 四位号段，首发 **`7000`**（经典十三水）；变体预留 `7001–7099`。玩法消息：`msg_id = game_id * 100 + slot`（`700000–700099`）；玩法错误码：`err = game_id * 1000 + slot`（`7000000+`）。
- 短名：`sss`（日志 / ClientTrace / 幂等键前缀）。
- 十三水为 **阶段制**（发牌→摆牌→比牌结算），非实时 tick；倒计时与托管对齐杭麻/比鸡模式。
- 不做微服务拆分；牌桌状态在房间内存，结算走 `WalletService` + `ledger` 幂等。
- 首发人数：**2–4 人**（最大 4；4 人用满 52 张）；匹配凑满模板 `players` 后建房；**不允许旁观**。
- **禁止**客户端自报牌型、水数或输赢；客户端只上报墩内牌序/确认/是否报到，服务端校验并结算。
- 与比鸡并行存在时，大厅模板、协议、单测、lab 路由均独立，禁止共用规则表。

## 2. 系统概述

### 2.1 产品目标

在现有棋牌大厅增加 **十三水金币场**：选场 → 入座准备 → 发 13 张 → 摆三墩（或特殊报到）→ 比牌计水结算。体验强调「组牌策略感、逐墩亮牌与打枪戏剧性、水数清晰可对账」；数值上底分 × 水数可控，便于运营调场。

### 2.2 与平台关系

```
[网页客户端] --WSS--> Pandora 单体
                         │
              ┌──────────┼──────────┐
              ▼          ▼          ▼
           大厅/匹配   十三水 RoomGame   钱包/活动/后台
              │          │
              │     game_id=7000
              │     SssTable 状态机
              └──────────┘
```

- 匹配：复用 `room_template`（`game_id=7000`）。
- 对局：实现 `IRoomGame`（如 `SssRoomGame`），`GameRegistry` 注册；规则在 `SssTable`。
- **禁止**再往 `Room` 增加十三水平行字段。

### 2.3 核心用户路径

1. 登录 → 大厅「十三水·初级场」  
2. 快速匹配凑齐 2–4 人 → 入座  
3. 全体准备 → 发牌（每人 13 张）  
4. 摆牌阶段：分配头/中/尾并确认；若构成特殊牌型可选「报到」  
5. 全员确认或超时 → 比牌（普通逐墩或特殊牌型）→ 打枪/全垒打结算  
6. 结算金币 → 可再准备下一局或离开

## 3. 规则需求（权威摘要）

细则落地后同步 `docs/十三水游戏规则.md`；与本文冲突时以 **已确认的 SPEC + 规则文档** 为准。以下为需求级默认（福建/华东常见无王玩法）。

### 3.1 牌具与人数

| 项 | 首发默认 |
|----|----------|
| 牌副 | 一副扑克去掉大小王，**52 张** |
| 人数 | **2–4 人**（最大 4；每人 13 张；4 人用满整副，2/3 人时余牌不发） |
| 发牌 | 服务端洗牌后每人发满 13 张；**首局随机起始座位，之后由上局净赢水最多者的下家起发**（并列则座位号小者优先） |

### 3.2 点数与花色

**点数（大 → 小）**：A > K > Q > J > 10 > 9 > 8 > 7 > 6 > 5 > 4 > 3 > 2。  
**顺子中的 A**：A2345 为最小顺，10JQKA 为最大顺；不允许 JQKA2 等绕接。  
**花色**：普通比牌 **不比花色**（同型同点完全一致则该墩 **平局 0 水**，§10 #2）。特殊牌型「凑一色 / 至尊清龙」等按花色定义判定，见 §3.7。

### 3.3 中墩 / 尾墩牌型（五张，大 → 小）

```
同花顺 > 铁支 > 葫芦 > 同花 > 顺子 > 三条 > 两对 > 对子 > 乌龙
```

| 牌型 | 定义 | 同型比较（摘要） |
|------|------|------------------|
| 同花顺 | 同花且五张连续 | 比最大点（顺子序） |
| 铁支 | 四条 + 一张 | 比四条点数，再比单张 |
| 葫芦 | 三条 + 一对 | 比三条点，再比对子点 |
| 同花 | 同花非顺 | 从大到小比五张点 |
| 顺子 | 连续非同花 | 比最大点（顺子序） |
| 三条 | 三张同点 + 两散 | 比三条点，再比两散（大→小） |
| 两对 | 两对 + 一散 | 比大对、小对、再比单张 |
| 对子 | 一对 + 三散 | 比对子点，再比三散（大→小） |
| 乌龙 | 其余 | 从大到小比五张点 |

### 3.4 头墩牌型（三张，大 → 小）

头墩 **不计同花、不计顺子**（三张同花/顺子只按点数结构认对子或散牌）。

```
三条 > 对子 > 乌龙（散牌）
```

| 牌型 | 定义 | 同型比较 |
|------|------|----------|
| 三条 | 三张同点 | 比点数 |
| 对子 | 一对 + 单张 | 比对子点，再比单张 |
| 乌龙 | 三张互不相同点 | 从大到小比三点 |

### 3.5 摆牌约束

- 头墩恰好 3 张，中墩、尾墩各恰好 5 张；三墩合起来必须是发到的 13 张（无换牌、无弃牌）。  
- 必须 **头墩 ≤ 中墩 ≤ 尾墩**（用 §3.3 / §3.4 完整比较；头墩与中墩比较时，将头墩视为「仅三条/对子/乌龙」的三张牌型，与中墩五张牌型按「三条 < 中墩任意五张牌型中的两对及以下时可比较点数」的规则在 SPEC 中用比较函数锁死：  
  **实现约定**：比较「墩 A ≤ 墩 B」时，先比牌型等级（头墩三条等级等同中/尾「三条」，头墩对子等同「对子」，头墩乌龙等同「乌龙」），再比点数细节；头墩永不具备同花/顺子/两对等五张专属牌型等级。  
- 非法提交：返回错误，不进入比牌；超时未确认：服务端按策略代摆合法牌（见 FR-SSS-33）。  
- **特殊牌型报到**：若 13 张满足 §3.7，玩家可在摆牌阶段选择「报到」；报到成功则本局该玩家 **不要求** 头≤中≤尾的普通摆法（可按协议提交特殊类型枚举 + 可选展示分墩）。未报到但实际构成特殊牌型时：**不自动报到**（避免误触高倍），仍按普通摆牌校验。

### 3.6 普通比牌与水数

对桌上 **任意两名未走特殊牌型结算路径的玩家**，两两比较三墩：

1. 头墩比头墩、中墩比中墩、尾墩比尾墩。  
2. 每墩：大者从对方赢得该墩水数；平局 0 水。  
3. **基础水数**（胜方得、负方失，符号相反）：

| 墩 | 条件 | 水数 |
|----|------|------|
| 头墩 | 普通胜 | 1 |
| 头墩 | 以 **三条** 胜（冲三） | 3 |
| 中墩 | 普通胜 | 1 |
| 中墩 | 以 **葫芦** 胜 | 2 |
| 中墩 | 以 **铁支** 胜 | 8 |
| 中墩 | 以 **同花顺** 胜 | 10 |
| 尾墩 | 普通胜 | 1 |
| 尾墩 | 以 **铁支** 胜 | 4 |
| 尾墩 | 以 **同花顺** 胜 | 5 |

说明：上表「以 X 胜」指胜方该墩牌型为 X（或更优且按该档计）；若胜方为同花顺，只取同花顺档，不叠加普通 1 水。细则用牌例在规则文档锁死。

4. **打枪**：若 A 对 B 三墩全胜（无平局），则 A、B 之间本局普通水数合计 **×2**（打枪翻倍）。  
5. **全垒打**：若人数 ≥ 3，且一人对其余 **每一个** 对手都打枪，则该玩家与每名对手之间的水数在打枪之后再 **×2**（即相对普通合计最高可达 ×4）。2 人局无全垒打。  
6. **倒水通赔**（仅当比牌时仍检出非法墩序，例如代摆 bug 或作弊路径）：倒水者对其他每人按「每墩按该墩最大可能输水」赔付，且视为被每人打枪（三墩全负）；不享受特殊牌型。正常客户端路径应在确认阶段拦截，通赔为兜底。  
7. 一局某玩家净水数 = 对所有其他玩家两两结算水数之和（含打枪/全垒打）+ 特殊牌型路径水数（§3.7）。  
8. **金币**：`delta_gold = 净水数 × base_score`；再按场次 `rake_bp` 从**本局净盈利的赢家**盈利中抽水（与平台一致）。

### 3.7 特殊牌型（报到 · 首发启用）

满足下列**全盘 13 张**条件且玩家选择报到时，该玩家进入特殊牌型路径：**不再与他人做普通三墩逐墩比**，而按特殊牌型水数向每个「非更高特殊牌型」的对手收取（见下）。同类只取最高一档，不叠加。

| 优先级（高→低） | 名称 | 条件（摘要） | 向每人收取水数 |
|-----------------|------|--------------|----------------|
| 1 | 至尊清龙 | 同花色 A→K 一至十三张（同花一条龙） | 108 |
| 2 | 一条龙 | A→K 各一张（花色不限） | 36 |
| 3 | 十二皇族 | 13 张均为 J/Q/K/A | 24 |
| 4 | 三同花顺 | 三墩皆为同花顺（头墩三张同花且连续，中尾同花顺） | 20 |
| 5 | 三分天下 | 三组铁支（三组四条，余一张） | 20 |
| 6 | 全大 | 13 张点数均 ≥ 8（含 8/9/10/J/Q/K/A） | 10 |
| 7 | 全小 | 13 张点数均 ≤ 8（含 A 时 A 作 1 仅用于本判定？**首发：A 只做大牌，全小不含 A**，点数均为 2–8） | 10 |
| 8 | 凑一色 | 13 张全为黑色（♠♣）或全为红色（♥♦） | 10 |
| 9 | 四套三条 | 四组三条 + 一张 | 6 |
| 10 | 五对三条 | 五对 + 一条（即五对 + 一张凑成的「三条」结构按流行定义：五对+三张同点） | 5 |
| 11 | 六对半 | 六对 + 一张 | 4 |
| 12 | 三顺子 | 三墩皆可摆成顺子（头墩三张连续） | 3 |
| 13 | 三同花 | 三墩皆同花（头墩三张同花） | 3 |

**特殊 vs 普通**：特殊牌型玩家向每名普通（未报到或报到失败）玩家收取上表水数；**不参与打枪 / 全垒打**。

**特殊 vs 特殊**：只比较优先级；高者向低者收取 **高者表内水数**；同优先级 **互不收水（平）**。

**多人特殊 + 多人普通**：先处理特殊之间，再由每个特殊向每个普通按上表收费；普通玩家之间仍按 §3.6 两两普通比牌（含打枪）。

牌例与边界（如三同花是否允许含同花顺墩、五对三条精确牌张）在 `docs/十三水游戏规则.md` 与 SPEC 用用例锁死。

## 6. 协议需求（概要）

详细字段在后续 `docs/十三水游戏-SPEC.md` 与 `proto/game_sss.proto` 锁定。需求级消息包括：

| 方向 | 用途 |
|------|------|
| S→C | 开局发牌、摆牌倒计时、他人确认/报到状态、比牌逐墩与两两结果、打枪/全垒打、结算、重连快照 |
| C→S | 提交/修改三墩、确认锁定、特殊报到、准备、离开 |

`msg_id`：`700000–700099`；错误码：`7000001+`（如非法摆牌、倒水、无效报到、重复确认等）。

## 7. 状态机（牌桌）

```
WaitReady → Deal → Arrange → Compare → Settle → WaitReady
                ↘（解散/全离）→ Closed
```

| 状态 | 行为 |
|------|------|
| WaitReady | 入座、准备；全员准备 → Deal |
| Deal | 洗牌发牌 → Arrange |
| Arrange | 接受摆牌/报到/确认；全锁或超时 → Compare |
| Compare | 服务端算水并广播逐墩与特殊结果 → Settle |
| Settle | 账变、结算面板 → WaitReady（或结束房间） |

## 8. 验收标准（首发 P0）

1. 大厅可匹配 `game_id=7000`，2–4 人开局并发 13 张。  
2. 合法摆牌可确认；倒水拒绝；超时有合法代摆且不自动报到。  
3. 普通牌型序、头墩三张规则、水数表、打枪/全垒打与 §3 一致（单测覆盖）。  
4. 特殊牌型报到校验与 §3.7 水数路径正确；与普通、多特殊并存场景有用例。  
5. 结算金币 = 净水 × 底分；赢家 `rake_bp` 抽水；ledger 可查且幂等。  
6. 断线重连可继续摆牌或看到比牌/结算。  
7. 顶号旧端失去操作权；无旁观。  
8. Web 正式桌 + `/sss-lab` 可完成「摆牌→比牌→金币变化」闭环。  
9. 模板关闭后不可再匹配。

## 10. 已确认决议

| # | 问题 | 决议 |
|---|------|------|
| 1 | 首发最大人数 | **4**（2–4 人） |
| 2 | 同墩完全相同 | **平局 0 水**（不比花色） |
| 3 | 打枪 / 全垒打 | **启用**（打枪 ×2；全垒打再 ×2） |
| 4 | 特殊牌型 | **启用 §3.7 表**；须玩家主动报到；超时代摆不报到 |
| 5 | 抽水 | **`rake_bp` 赢家抽水** |
| 6 | 发牌起始 | **上局净赢水最多者下家**（首局随机） |
| 7 | 超时代摆 | **固定启发式 + 单测**；不自动特殊报到 |
| 8 | 旁观 | **否** |
| 9 | `game_id` / 短名 | **7000** / `sss` |
| 10 | 全小是否含 A | **不含 A**（A 仅作大牌） |
| 11 | 倒水 | **确认阶段拒绝**；比牌兜底通赔 |
